# AIOps 运维工单多智能体系统 · 项目简报

## 1. 一句话定位

面向 SRE 场景的多 Agent 系统：用户提交运维工单（pod 大量 OOM、接口 5xx 突增、数据库慢查询），系统内多个 Agent 分工协作，自动完成「意图识别 → 数据检索 → 根因推理 → 工单回复」，信息不足时主动向提交人追问，最终产出**带证据、带置信度、带处置建议**的事故报告。对外是一个聊天式工单页，对内是"多 Agent 编排 + 工具可靠性 + 证据化推理"的工程系统（不是套壳 ChatGPT + 工具）。

## 2. 核心场景（首批垂直切片只做一类）

- 主场景：**接口 5xx 突增**（本地集群有真实数据可验证）
- 扩展场景：pod OOM、数据库慢查询、依赖服务抖动

## 3. 系统架构

**5 个业务 Agent + 1 个编排引擎**：

| Agent | 职责 | 主要工具 |
|---|---|---|
| 意图识别 Agent | 判定工单类型、抽取实体（服务/pod/时间窗/命名空间）、评估信息完整性、生成追问 | — |
| 指标检索 Agent | 用 PromQL 拉取指标并解释趋势 | Prometheus |
| 日志解析 Agent | 在故障时间窗内检索/解析异常日志 | Loki（或 K8s 容器日志） |
| 根因推理 Agent | 综合指标+日志，提假设、补查证据、交叉验证、给置信度；证据不足/置信度低时要求补查或转人工 | 复用指标/日志工具 |
| 工单回复 Agent | 生成结构化事故报告（时间线/根因/证据/建议），低危动作可一键触发 | 工单系统 |

**编排引擎**：负责 Agent 间多轮结构化消息传递（观察集 + 假设集 + 已排除项 + 待补项）、状态机维护、断点恢复；HITL「等待补充信息」「转人工」是一等状态。

## 4. 关键约束（核心设计输入，非可选）

1. **工具调用失败 / 超时**：每个工具需独立超时、重试、降级；指标查询可能耗时较长，需异步/缓存处理。
2. **信息不全需追问**：工单可能缺关键信息，系统要主动提问，人回复后从断点恢复继续。
3. **多轮交互**：一次工单处理不能一口气跑完，Agent 之间要多轮、可回环（根因缺证据时回去补查）。
4. **根因防幻觉**：所有结论必须附真实证据引用（PromQL 结果、日志片段、kubectl 事件），带置信度；低于阈值转人工。

## 5. 功能需求清单

- 工单生命周期：提交 → 意图分类 → 排队/处理中 → 等待补充 → 已解决 / 转人工，含满意度与历史
- 多 Agent 编排：有回环的任务图、多轮消息、断点恢复
- 工具层：工具注册表、结构化 schema、参数校验、每工具超时/重试/降级
- 追问 HITL：信息完整性判定、生成追问、挂起、恢复
- 根因推理：假设空间、证据引用、置信度、交叉验证、转人工
- 产出：事故报告（时间线/根因/证据/建议）、低危操作一键触发（回滚/扩缩），高危转人工
- 案例沉淀：已解决工单向量化入库（Milvus），同类工单秒级给出相似历史处置
- **自可观测**：单次工单处理 = 一条分布式 Trace（Agent=span、工具调用=子 span），配工具成功率/延迟/LLM token 指标、推理回放
- 管理面：Agent 配置热更新、工具权限、Prompt 管理

## 6. 技术选型（已定，勿再纠结）

- 语言/框架：**Go**；多 Agent 编排用 eino（仓库已有 eino 经验）或自写轻量状态机；内部 gRPC/HTTP
- AI：复用既有 provider 工厂 + Prompt 模板 + 结构化输出模式（见 `02-reuse-prehire.md`）
- 数据源：Prometheus（现成）、Jaeger（现成）、日志（**Loki 需补，或走 `kubectl logs`/client-go**）、DB 慢查询（接 PG 或轻量模拟）
- 存储：工单/会话状态入 PostgreSQL，会话/限流用 Redis（均有）
- 部署：同一套 Docker + Helm + kind + OTel 模式
- 案例库：Milvus 向量检索（复用已有 RAG 经验）

## 7. 与现有环境的关系

- **代码/仓库独立**：不并入 PreHire 仓库，独立新仓库/工作区。
- **环境/数据复用**：工具查询对象指向 PreHire 本地 kind 集群的 Prometheus/Jaeger（见 `03-data-source.md`），使工单、查询、结论都是真实的，而非 mock。叙事闭环：这套 AIOps 正在运维 PreHire 自身。

## 8. 演示原则

- 演示必须有真实故障：现场制造故障（杀 Pod / 限内存触发 OOMKilled）→ 提工单 → Agent 查数查日志 → 根因 → 回滚恢复，全程可回放；并演示一次工具超时/降级。
- 面试高分区：证据化根因、工具降级容错、自可观测 + 推理回放。
