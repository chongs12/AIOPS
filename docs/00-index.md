# AIOps 项目交接知识包

> 本目录是给「另一个目录下」的 AIOps 开发智能体准备的启动知识。该智能体**无法访问 PreHire（makejob）仓库**，因此把项目简报、可借鉴清单、真实数据源三类信息抽成自包含文档。

## 文件清单

| 文件 | 内容 |
|---|---|
| `01-brief.md` | AIOps 项目简报：定位、架构（多 Agent + 工具 + HITL）、关键约束、功能清单、技术选型、期望产出 |
| `02-reuse-prehire.md` | 从 PreHire 可借鉴/复用/对标的**设计与实现**（AI 工程、缓存、限流、MQ 异步、可观测、部署、安全、目录规范），全部按「实际代码」编写 |
| `03-data-source.md` | 新项目工具的**真实数据源环境**：指向 PreHire 本地 kind 集群的可观测栈——指标名、服务拓扑、访问地址、缺什么、如何制造真实故障 |

## 用法

1. 把本目录（或其中三个 md）整体复制到 AIOps 新项目仓库（如 `docs/` 下）。
2. 给开发智能体的任务提示词里，明确引用这三个文件作为上下文/记忆。
3. 提示词模板见本包使用者的对话（或 `01-brief.md` 结尾的"期望产出"一节）。

## 关键约定（写给新智能体，避免跑偏）

- **代码/仓库独立**：AIOps 是新仓库，不并入 PreHire；但**环境/数据复用**——工具的查询对象是 PreHire 集群的真实 Prometheus/Jaeger。
- **复用优先**：优先对标 `02-reuse-prehire.md` 里已经踩平的设计（尤其 `pkg/ratelimit` 的故障语义、`pkg/cache` 的三防），不要另起炉灶重复造轮子。
- **垂直切片**：先做「接口 5xx 突增」一类工单打通全链路，再扩展其他工单类型。
