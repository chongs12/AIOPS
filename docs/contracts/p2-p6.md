# 契约：P2–P6 新增端点（请求/响应要点）

## P3 · GET /tickets/{id}/replay
`{trace_id, trace_url, events:[{ts, type: message|observation|audit, actor, title, detail, ref_id}]}`，升序稳定排序。

## P4 · 复查与通知
- 处置成功（工单 actions / console k8s actions）→ 自动入队 `verify_recovery`（等待 WaitSeconds）。
- 复查通过 → 工单 resolved + 系统消息"✅ 复查通过…允许 resolved/investigating 状态复查"。
- webhook POST Notify.WebhookURL：`{event, ticket_id, title, status, confidence, trace_url}`。

## P5 · GET /tickets/stats
`{by_status, by_priority, avg_resolve_seconds, avg_first_response_seconds, resolved_24h, total}`。

## P5 · GET /cases?limit= / GET /cases/{id}
列表返回 `items:[{ticket_id, type, service, root_cause, summary, created_at}]`；详情 404 或工单+报告。

## P6 · POST /alerts/webhook
入参：Alertmanager v2 `{alerts:[{labels,annotations,fingerprint}]}` 或简化 `{title,content,service,severity}`。
出参：`{items:[{ticket_id, deduped}]}`；指纹 24h 幂等；severity→priority（critical→P0, warning→P1）。
